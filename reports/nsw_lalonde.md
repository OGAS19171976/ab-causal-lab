# 真实处置的验证：LaLonde NSW（Dehejia–Wahba 子样本）

这份数据与 `reports/real_vs_synthetic.md` 里那份（MovieLens）**分工不同**：
MovieLens 是自造分流的 A/A，只能校准口径与方差；这一份是**真的随机化**，
而且有**公开的实验基准**，所以它能验证效应。

  event_log       1335 行  sha256 c4763e35102d… ✓

  上游原始文件的 sha256 也记在 provenance 里 —— 源站是可变 URL，
  而结论挂在具体某一份字节上。

## 2. 接入：与 MovieLens 走同一套 SQL
  真实数据入口：data/real_nsw → build/nsw_traffic（parquet）
    exposure_log         445 行，ds 1976-01-01 ~ 1976-01-01
    event_log          1,335 行，ds 1974-01-01 ~ 1978-01-01

  DWD 落 445 个单元；三张源表 -> 12 张数仓表，一条 SQL 都没改

## 3. 复现公开基准（明细路径，手算）
  处置组 re78 均值 = 6349.1435（n=185）
  对照组 re78 均值 = 4554.8011（n=260）
  **ATT = +1794.34**（SE 671.00, t = +2.674）
  发表值 +1794.34 —— 偏差 0.0024（容差 0.05）

## 4. 两条路径同一个数：明细 vs ADS 充分统计量
  明细：τ̂ = +1794.3424，z = +2.674146
  ADS ：τ̂ = +1794.3424，z = +2.674146
  偏差 6.66e-15 —— 两条路径用的是同一批充分统计量

## 5. 这份数据教的三件事
  ① **SRM 在这份数据上不能作为证据**：实测份额 0.4157 / 0.5843
     按声明（= 实测）权重算 χ² = 0.0000 —— 恒为 0，因为权重就是从同一批数据反推的；
     若按 1:1 这个『想当然』的权重算，χ² = 12.64 —— 会得出『分流坏了』的错误结论。
     源站没有给出分配比例，所以**这份数据上 SRM 无解**：设计权重必须来自声明，而声明我们没有。
  ② **CUPED 在这份真实数据上几乎不省样本**：前置（re74+re75）与 re78 的相关只有 +0.0929，
     于是方差缩减 ≈ **0.00863**（合成器上是 0.63，MovieLens 上是 0.04）。
     这不是实现问题，是**收入数据的真实性质**：去年的收入几乎预测不了两年后的收入。
     这也说明合成数据上的 CUPED 结论不能外推 —— 正是接真数据买到的东西。
  ③ **观察性对照没做**（LaLonde 那道名题的正面部分）：用 PSID/CPS 当对照组
     会得到偏得很远的估计（原论文里甚至出现过负号）。本仓库这一步只验证了
     **实验臂**。顺带记一个实测到的事实：源表 `data/real_nsw/user_profile.parquet`
     里带着 age/education/black 等协变量，但**归一化把它们丢掉了** ——
     它只保留契约列（上面接入报告里印着『丢掉的多余列』）。
     所以下一轮做倾向得分对照，要么扩契约、要么直接读源表。

## 6. 边界（如实写）
  * 这份数据**没进 `check_real_traffic.py` 那扇门**：门写死了 `data/real/`。
    这个脚本直接调它的 `validate`（契约只有一份实现），但『多个数据集各自成门』是另一件事，留着；
  * 两个臂是**真实随机化**，所以这里的 z 可以读成效应检验；但 n=445、t=2.67，
    『显著』与『估得准』仍是两件事（发表值本身也有 SE 671）；
  * 时间维度是**映射**出来的（re74/re75/曝光/re78 落在四个日期上），不是原始数据里的观测时间；
  * **契约之外的列会被静默丢掉**（归一化只保留契约列）——这次丢的是协变量，
    报告里印出来了，所以不算静默；但它意味着『源表里有的列』不等于『链路里能用的列』。
